# ESP-IDF 开发环境搭建记录

[English](dev-setup.en.md)

本文记录在本机（Windows 10/11）上为本项目安装 VS Code + ESP-IDF 的流程，以及启动/编译过程中遇到的错误与修复方法。

---

## 路径约定

下文用占位符表示路径，请按你的实际安装位置替换：

| 占位符 | 含义 | 说明 |
|--------|------|------|
| `<IDF_ROOT>` | ESP-IDF 安装根目录 | 建议选非 C 盘，例如某盘的 `Espressif` 目录 |
| `<项目根>` | 本仓库根目录 | 即包含 `main/`、`CMakeLists.txt` 的目录 |
| `<版本>` | ESP-IDF 版本号 | 本文以 `5.4.2` 为例 |

项目内文件一律用**相对路径**（相对于 `<项目根>`）：

```
<项目根>/
├── main/
├── .vscode/
├── build/              # 编译输出（git 忽略）
├── sdkconfig           # 由 set-target 生成
└── docs/开发环境搭建.md
```

ESP-IDF 与工具链目录结构（位于 `<IDF_ROOT>`，与项目分离）：

```
<IDF_ROOT>/
├── .espressif/
│   └── <版本>/
│       └── esp-idf/          # ESP-IDF 源码
├── tools/                    # 编译器、cmake、ninja、openocd 等
│   ├── eim_idf.json
│   └── Microsoft.v<版本>.PowerShell_profile.ps1
└── dist/                     # 下载缓存
```

## 二、安装流程

### 1. 安装 VS Code 扩展

**扩展地址：**

- Visual Studio Marketplace：  
  https://marketplace.visualstudio.com/items?itemName=espressif.esp-idf-extension

**命令行安装：**

```powershell
code --install-extension espressif.esp-idf-extension
```

**官方文档：**

- ESP-IDF Extension 安装说明：  
  https://docs.espressif.com/projects/vscode-esp-idf-extension/en/latest/installation.html
- 故障排查：  
  https://docs.espressif.com/projects/vscode-esp-idf-extension/en/latest/troubleshooting.html

### 2. 安装 EIM（ESP-IDF Installation Manager）

EIM 是 Espressif 官方推荐的 ESP-IDF 安装管理工具，VS Code 扩展 v2.x 通过它发现和配置 ESP-IDF。

**安装方式（winget）：**

```powershell
winget install Espressif.EIM-CLI --accept-package-agreements --accept-source-agreements
```

**EIM 相关文档：**

- CLI 命令参考：  
  https://docs.espressif.com/projects/idf-im-ui/en/latest/cli_commands.html
- 自定义安装路径 FAQ：  
  https://docs.espressif.com/projects/idf-im-ui/en/latest/faq.html

### 3. 安装 ESP-IDF 到自定义目录（命令行，推荐）

GUI 向导默认安装到系统盘 `C:\esp`；若希望工具链与源码都在自选盘符，使用以下命令（将 `<IDF_ROOT>` 换成你的路径）：

```powershell
eim install `
  -p "<IDF_ROOT>/.espressif" `
  --tool-install-folder-name "<IDF_ROOT>/tools" `
  --tool-download-folder-name "<IDF_ROOT>/dist" `
  --activation-script-path-override "<IDF_ROOT>/tools" `
  --esp-idf-json-path "<IDF_ROOT>/tools" `
  -i v5.4.2 `
  -t esp32s3 `
  -n true `
  -a true `
  --pypi-mirror https://pypi.tuna.tsinghua.edu.cn/simple
```

**ESP-IDF 源码地址：**

| 来源 | URL |
|------|-----|
| GitHub 官方 | https://github.com/espressif/esp-idf.git |
| 国内镜像（EIM 自动选用） | https://git.espressif.com.cn/espressif/esp-idf.git |
| 工具链下载镜像 | https://dl.espressif.cn/github_assets |
| PyPI 镜像（清华） | https://pypi.tuna.tsinghua.edu.cn/simple |

安装完成后验证：

```powershell
eim list --esp-idf-json-path "<IDF_ROOT>/tools"
eim select v5.4.2 --esp-idf-json-path "<IDF_ROOT>/tools"
```

### 4. 配置 VS Code

在 `<项目根>/.vscode/settings.json`（或用户设置）中指定 EIM 配置：

```json
{
  "idf.eimIdfJsonPath": "<IDF_ROOT>/tools/eim_idf.json",
  "idf.currentSetup": "<eim_idf.json 中 idfInstalled[].id>"
}
```

> `idf.currentSetup` 的值来自 `<IDF_ROOT>/tools/eim_idf.json` 里对应安装项的 `id` 字段，**不是** `IDF_PATH` 路径。每台机器不同，需自行查看该文件。

在 VS Code 中：

1. `Ctrl+Shift+P` → **ESP-IDF: Select Current ESP-IDF Version** → 选择 `v5.4.2`
2. `Ctrl+Shift+P` → **ESP-IDF: Doctor Command** 检查环境

### 5. 初始化并编译项目

```powershell
# 激活 ESP-IDF 环境（脚本由 EIM 生成，路径随版本变化）
. <IDF_ROOT>/tools/Microsoft.v5.4.2.PowerShell_profile.ps1

cd <项目根>
idf.py set-target esp32s3
idf.py build
```

## 三、遇到的错误与修复

### 错误 1：OpenOCD error monitor 初始化失败

**现象：**

```
Error initializing OpenOCD error monitor: Cannot convert undefined or null to object
```

**原因：**

- 项目缺少 `sdkconfig`（尚未执行 `idf.py set-target`）
- VS Code 扩展未正确绑定 ESP-IDF 安装（`idf.currentSetup` 未设置或填错）
- 曾在 `idf.customExtraVars` 中只写了部分变量，覆盖了 EIM 注入的完整环境

**修复：**

1. 在 PowerShell 中于 `<项目根>` 执行 `idf.py set-target esp32s3` 生成 `sdkconfig`
2. 在 `.vscode/settings.json` 中设置正确的 `idf.eimIdfJsonPath` 和 `idf.currentSetup`
3. **删除** `idf.customExtraVars` 中不完整的覆盖配置，让扩展从 EIM 自动读取 PATH

---

### 错误 2：VS Code 编译失败 — CMake / Ninja 找不到

**现象：**

```
Something went wrong while trying to build the project
Error: CMake or Ninja executables not found
```

**原因：**

`idf.customExtraVars` 中只配置了 `IDF_PATH`、`IDF_TOOLS_PATH` 等，**没有包含 PATH**，导致扩展覆盖了 EIM 自动注入的工具链路径，找不到 `cmake` 和 `ninja`。

Doctor 报告中表现为：

```
Access to CMake in environment PATH undefined
Access to Ninja in environment PATH undefined
```

**修复：**

从 `.vscode/settings.json` 中**移除** `idf.customExtraVars`，仅保留 EIM 相关两项（路径替换为你的 `<IDF_ROOT>` 和实际 `id`）：

```json
{
  "idf.eimIdfJsonPath": "<IDF_ROOT>/tools/eim_idf.json",
  "idf.currentSetup": "<你的 setup id>"
}
```

重载 VS Code 窗口后，扩展会从 EIM 配置自动注入完整 PATH。

> PowerShell 命令行编译通常正常，因为激活脚本 `Microsoft.v<版本>.PowerShell_profile.ps1` 会设置完整 PATH。

---

### 错误 3：Doctor 报 sdkconfig / launch.json / c_cpp_properties.json 缺失

**现象：**

```
ENOENT: no such file or directory, access 'sdkconfig'
ENOENT: launch.json
ENOENT: c_cpp_properties.json
```

**修复：**

| 文件（相对项目根） | 处理方式 |
|--------------------|----------|
| `sdkconfig` | 执行 `idf.py set-target esp32s3` 自动生成 |
| `.vscode/launch.json` | 从扩展模板创建（GDB Adapter 调试配置） |
| `.vscode/c_cpp_properties.json` | 从扩展模板创建（`compileCommands` 指向 `build/compile_commands.json`） |

扩展模板位置：  
`%USERPROFILE%\.vscode\extensions\espressif.esp-idf-extension-<version>\templates\.vscode\`

---

### 错误 4：工具链解压不完整 — gcc 找不到 cc1

**现象：**

```
xtensa-esp-elf-gcc.exe: fatal error: cannot execute 'cc1': CreateProcess: No such file or directory
```

**原因：**

EIM 安装时 `xtensa-esp-elf` 的 zip 解压失败，`libexec` 等目录变成了空文件而非文件夹。安装日志中可能有：

```
ZipArchive decompression failed ... Falling back to PowerShell approach.
```

**修复：**

手动用 PowerShell 重新解压（路径相对于 `<IDF_ROOT>`，版本号以实际为准）：

```powershell
$root = "<IDF_ROOT>"
$ver  = "esp-14.2.0_20241119"   # 以 tools/xtensa-esp-elf/ 下实际目录名为准

Remove-Item -Recurse -Force "$root/tools/xtensa-esp-elf/$ver"
New-Item -ItemType Directory -Force -Path "$root/tools/xtensa-esp-elf/$ver"
Expand-Archive -Path "$root/dist/xtensa-esp-elf-14.2.0_20241119-x86_64-w64-mingw32.zip" `
  -DestinationPath "$root/tools/xtensa-esp-elf/$ver" -Force
```

验证 `cc1.exe` 存在于：

```
<IDF_ROOT>/tools/xtensa-esp-elf/<工具版本>/xtensa-esp-elf/libexec/gcc/xtensa-esp-elf/<gcc版本>/cc1.exe
```

---

### 错误 5：Git Bash 中 idf.py 不执行

**现象：**

在 Git Bash / Cursor 终端中运行 `idf.py`，只打印 MSYS 警告后无任何操作，`sdkconfig` 不会生成。

**原因：**

ESP-IDF v5.4+ 检测到 `MSYSTEM` 环境变量（Git Bash 特有）时，跳过 `main()` 不执行。

**修复：**

- **编译、烧录等操作统一使用 PowerShell 终端**
- 或在脚本中清除 MSYS 变量后直接调用 python：

```powershell
Remove-Item Env:MSYSTEM -ErrorAction SilentlyContinue
$idf = "<IDF_ROOT>/.espressif/<版本>/esp-idf"
$py  = "<IDF_ROOT>/tools/python/v5.4.2/venv/Scripts/python.exe"
& $py "$idf/tools/idf.py" build
```

（在 `<项目根>` 下执行。）

---

### 错误 6：idf.currentSetup 填错

**现象：**

扩展无法识别 ESP-IDF 安装，Doctor 中 "ESP-IDF Setups" 为空。

**原因：**

将 `idf.currentSetup` 设为了 `IDF_PATH` 路径（如 `<IDF_ROOT>/.espressif/<版本>/esp-idf`），正确值应是 `eim_idf.json` 中的 **id** 字符串。

**修复：**

查看并复制正确 id：

```powershell
Get-Content "<IDF_ROOT>/tools/eim_idf.json" | Select-String '"id"'
# 使用 idfInstalled[].id 的值填入 idf.currentSetup
```

---

### 错误 7：EIM GUI 向导默认装到系统盘

**现象：**

运行 `eim wizard` 时，安装路径默认为 `C:\esp`，工具链到 `C:\Espressif\tools`。

**处理：**

- 若需自定义盘符，**取消向导**，改用第二节第 3 步的命令行 `eim install`
- 若已在向导中选了路径但尚未开始下载，`Ctrl+C` 取消即可，一般不会留下完整安装

## 四、日常开发命令

在 `<项目根>` 下执行：

```powershell
# 1. 激活环境（每个新 PowerShell 窗口需执行一次）
. <IDF_ROOT>/tools/Microsoft.v5.4.2.PowerShell_profile.ps1

# 2. 进入项目（若尚未在项目目录）
cd <项目根>

# 3. 编译
idf.py build

# 4. 烧录 + 串口监视（COMx 替换为实际端口）
idf.py -p COMx flash monitor

# 5. 查看已安装版本
eim list --esp-idf-json-path "<IDF_ROOT>/tools"
```

## 五、注意事项

1. **终端选择**：务必使用 **PowerShell**，不要用 Git Bash 运行 `idf.py`。
2. **不要手动写 `idf.customExtraVars`**：除非你能提供完整的 PATH 列表；否则让 EIM 自动管理。
3. **Python 警告可忽略**：`Python interpreter ... is not from installed venv` 是路径格式差异，不影响编译。
4. **ESP-ADF Path undefined**：未使用 ESP-ADF 框架，Doctor 中此提示可忽略。
5. **OpenOCD 报错**：若只用 UART 烧录、不做 JTAG 调试，OpenOCD 相关警告通常不影响编译和烧录。
6. **项目路径**：仓库目录名不含中文和空格，避免 ESP-IDF 路径兼容问题。
